R1.0 chooses the execution boundary for the new editorial foundation without changing the public runtime yet and without performing Record Birth.

The current application is a React 18 + Vite SPA whose Vercel configuration rewrites extensionless paths to `index.html`. R0.7 already established that this fallback behavior cannot be the future identity rule for unknown paths.

R1.0 therefore freezes a static-first publication runtime whose renderer consumes deterministic projections of admitted editorial state.

## 1. Runtime choice

The target publication shell is:

```text
Astro static output
  + React islands where interaction is genuinely required
```

The framework is an implementation choice of R1, not an ontology rule. Changing framework later does not change Record identity under R0.2.

R1.0 freezes the runtime family and boundary, not a package version. Dependency/version materialization occurs only when the target shell is introduced by a later R1 implementation cut.

The current React/Vite SPA remains the deployed legacy runtime at this cut.

## 2. Static-first authority model

The future public build pipeline is:

```text
canonical editorial files
        ↓
load
        ↓
validate R0 contracts
        ↓
reconstruct Record lineages
        ↓
apply explicit amendments
        ↓
resolve governance eligibility
        ↓
resolve language realization
        ↓
resolve route identity
        ↓
produce projection DTOs
        ↓
render static HTML / feeds / indexes
```

The publication renderer MUST NOT become semantic authority.

In particular:

```text
HTML != Record authority
Astro page != Record
React component != Record
Markdown file != Record by location alone
client state != language identity
URL slug != RecordId
repository name != System identity
```

## 3. Canonical state is local and build-time

The target public runtime does not crawl GitHub at request time to discover its ontology.

GitHub and other repositories may remain provenance/evidence sources, but admitted editorial state is represented locally in the Portfolio editorial registry and validated before publication.

Therefore:

```text
request-time GitHub crawl         forbidden as semantic authority
request-time ontology inference   forbidden
client-side Record reconstruction forbidden
```

Repository grounding may produce future ingestion tooling, but ingestion and admission remain separate operations.

## 4. Fail-closed build boundary

A public build MUST fail rather than silently repair authoritative contradictions such as:

```text
invalid Record lineage
RecordId reuse
kind mutation
incompatible current heads
invalid pinned reference
historical locator reassignment
duplicate canonical route
route/type contradiction
conflicting current governance
invalid language binding
```

A Record that is simply not eligible for public disclosure may be absent from the public projection without making the entire registry invalid.

However, a route or public projection that explicitly targets an unresolved, conflicted or ineligible Record MUST NOT be emitted as if valid.

## 5. Projection boundary

Pages and interactive components consume projection DTOs, not mutable authoritative stores.

Conceptually:

```text
Record Registry
   + Evidence
   + Governance
   + Route Registry
   + Language Registry
          ↓
     Projection Engine
          ↓
     Public DTO
       ├── Astro renderer
       ├── React island
       ├── Search index
       ├── RSS
       └── Sitemap
```

A renderer may format, sort or visually compose already-admitted public projection data. It may not upgrade a Claim, infer Evidence, change disclosure, mint a Record, bind a route or choose a different language identity.

## 6. React island boundary

React is retained for bounded interactive surfaces that need client execution.

Examples may later include:

```text
search interaction
architecture exploration
command palette
filtering
interactive evidence inspection
```

An island receives serialized projection data or a bounded client-only UI state. It MUST NOT receive authority to mutate canonical editorial identity.

Client-only state may express presentation preferences such as open/closed panels or query text. It cannot express authoritative facts such as:

```text
current Record head
public/private eligibility
canonical language
canonical route
Evidence support
maturity
Record lifecycle
```

## 7. Route runtime boundary

The future static shell materializes R0.7 rather than reproducing the SPA catch-all.

Record routes are generated from admitted route bindings.

```text
bound Record path       -> generated page
registered alias        -> explicit redirect/compatibility behavior
service/collection path -> explicit route
unknown path            -> 404 / unresolved
```

There is no rule of the form:

```text
unknown path -> home
```

Legacy compatibility routes remain explicit migration surfaces and are handled by R1.8, including `/work/agentic-systems` under R0-A1.

## 8. Language runtime boundary

Locale is path identity for canonical Record routes exactly as frozen by R0.7.

The future runtime MUST NOT use client language state to reinterpret one canonical URL as another language.

```text
/en/...    -> English realization required
/pt-br/... -> PT-BR realization required
```

If a current Record revision lacks the requested realization, the runtime produces an explicit unavailable/unresolved outcome rather than silently serving another language.

## 9. Server boundary

The editorial publication surface requires no always-on application server for semantic correctness.

The target foundation is compatible with static hosting on Vercel:

```text
build-time authority
static publication output
optional client islands
no request-time database required for canonical reading
no request-time GitHub dependency required for canonical reading
```

Future features may introduce server capabilities, but those services remain outside Record authority unless explicitly admitted by a later contract.

## 10. Legacy runtime coexistence

R1.0 does not delete or rewrite:

```text
package.json Vite scripts
vite.config.ts
src/main.tsx
current React components
vercel.json SPA rewrite
legacy public UI
```

Those files remain the current runtime until an explicit cutover step.

This makes the migration two-phase:

```text
first: build and validate the editorial substrate
then: cut public rendering over to the new shell
```

rather than changing framework and ontology simultaneously.
