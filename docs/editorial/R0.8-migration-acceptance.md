# R0.8 — Migration & Acceptance

Status: **FROZEN / COMPLETE**

Portfolio baseline: `main@d74a5b13bd746561d82b183f491a529d9701c57b`

Precondition: `R0_7_COMPLETE=true`.

R0.8 is the terminal constitutional cut. It proves that the complete R0.0 frozen Portfolio can be mapped into the R0.2–R0.7 world without retaining `Project` as ontology, losing frozen public semantics, manufacturing Evidence, exposing hidden private material or breaking legacy route identity.

R0.8 still performs **no public runtime migration** and **no Record Birth**.

```text
R0.0 frozen world
      ↓
identity / knowledge / evidence
representation / governance

      ↓
R0.8 migration map
      ↓

```

## Migration is not Birth

R0.8 reserves opaque `RecordId` values for durable entities that must survive migration.

```text
reserved RecordId != born Record
```

R1 must create the corresponding generation-zero revisions under R0.2 and compute their canonical payload and Revision identities. R0.8 therefore never invents RevisionIds or pinned Evidence bindings for entities that do not yet exist.

## Evidence reconciliation

The two overlapping frozen evidence catalogs are unioned by exact locator. Every locator receives exactly one treatment.

Existence-oriented source, document and deployment locators may become R0.4 Artifact births in R1.

Three locator-only items require fresh capture before they can support occurrence facets:

```text
https://vira.snelabs.space/ready
https://vira.snelabs.space/public/playback
https://www.youtube.com/watch?v=LnOd2kWTiGA
```

They are frozen as `recapture-required` because R0.4 requires digest and `observedAt` for occurrence evidence. R0.8 preserves the locator but refuses to manufacture historical runtime proof.

No `evidence.binding` is created during migration because such relations require exact born and pinned revisions.

## Route reconciliation

All eight frozen R0.0 public paths have a compatibility treatment.

```text
/              service route: home
/architecture  service route: architecture index
```

The six legacy `/work/:projectId` paths previously served both EN and PT via client state. They therefore remain planned language-negotiating compatibility entry points rather than invalid R0.7 aliases with ambiguous language identity.

For example:

```text
/work/vira
    -> /en/systems/vira
    -> /pt-br/systems/vira
```

Target Record routes obey R0.7 and use explicit locale identity. The old paths remain preserved; R0.8 does not enact redirects yet.

## Language reconciliation

For frozen Project and Architecture material that already contains EN/PT representations, the migration plan uses:

```text
canonical     en
translation   pt-BR
```

The two handbook publications are not forced to become bilingual solely because their surrounding legacy UI was localized. Translation remains optional under R0.7.

Exact language bindings are created only after R1 births the target revisions and realization digests exist.
