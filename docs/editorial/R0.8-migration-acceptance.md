R0.8 is the terminal constitutional cut. It does not redesign the public site and it does not yet perform Record Birth. It proves that the complete R0.0 frozen Portfolio can be mapped into the R0.2–R0.7 world without retaining `Project` as ontology, losing public identities, manufacturing Evidence, exposing private material or breaking legacy route identity.

The governing reconciliation is:

```text
R0.0 frozen world
      ↓ inventory identity
R0.2 identity substrate
      ↓
R0.3 knowledge kinds
      ↓
R0.4 evidence rules
      ↓
R0.5 representations
      ↓
R0.6 disclosure / maturity
      ↓
R0.7 route / language identity
      ↓
R0.8 migration map
      ↓
R1 materialization
```

## 1. Migration map is not Record Birth

R0.8 reserves opaque `RecordId` values for the durable entities that must survive the migration, but those reservations are not Records yet.

```text
reserved RecordId
    != born Record
```

R1 must materialize each reserved identity through a valid R0.2 generation-zero revision with a canonical payload owned by the appropriate R0.3–R0.6 contract.

This boundary prevents R0.8 from inventing payloads, RevisionIds or evidence bindings merely to make the migration appear complete.

## 2. Legacy Project decomposition

The six frozen Project identities are reconciled as follows:

```text
VIRA                         -> knowledge.system
XS Wallet                    -> knowledge.system
Agentic Systems & Foundry    -> knowledge.system
Transactional Support Bot    -> knowledge.system
SNE OS                       -> knowledge.system
VERIFY SYSTEMS               -> representation.publication
```

`Project` disappears as an ontology primitive.

VERIFY SYSTEMS is intentionally mapped to the same Publication identity already present in the frozen publication surface. R0.8 does not mint a duplicate System just because the old UI represented the paper through a Project card.

## 3. Legacy guarantee labels

R0.0 froze all Project guarantee labels but explicitly did not establish their epistemic status.

R0.8 therefore applies this rule:

```text
System project guarantee
    -> planned knowledge.claim
       with no automatic Evidence status

VERIFY SYSTEMS guarantee
    -> representation text
       inside the Publication migration
```

The labels are preserved verbatim. R1 may give planned Claims full scoped statements, but it may not silently strengthen the original wording or mark them established without R0.4 Evidence bindings.

## 4. Sanitized public migration

Two old visibility values require decomposition rather than literal copying.

Agentic Systems & Foundry used legacy `private`, while the public site already exposed an intentionally architectural description. The migrated Record therefore represents only that already-public safe form:

```text
record       public
source       private
evidence     none
disclosure   sanitized
```

Transactional Support Bot used legacy `case-study` and is migrated as:

```text
record       public
source       private
evidence     private
disclosure   sanitized
```

Neither mapping authorizes importing hidden implementation details. `sanitized` remains the R0.6 admission boundary, not a redaction engine.

## 5. Maturity is deliberately sparse

R0.8 does not infer maturity from visual polish, route existence or project prominence.

Only XS Wallet receives a maturity plan:

```text
pre-beta
```

because the frozen project source explicitly calls the public codebase a technical pre-beta. Other System maturity remains unclassified until a later explicit governance decision.

## 6. Architecture migration

All five frozen Architecture Explorer views become `representation.architecture` identities:

```text
systems
settlement
agents
realtime

```

Their principles, boundaries and guarantee text remain representation semantics, not Evidence.

Subjects are resolved from the frozen architecture source:

```text

settlement   -> Foundry Pay
agents       -> Agentic Systems & Foundry
realtime     -> VIRA
handoff      -> Transactional Support Bot
```

Foundry Pay receives one supporting `knowledge.system` reservation because it is explicitly named as the authority-owning System in the frozen settlement architecture. R0.8 does not generalize every diagram component into a global Record.

## 7. Publication migration

The frozen publication catalog becomes three Publication identities:

```text
VERIFY SYSTEMS               technical-paper
Production Systems Handbook  technical-paper
TypeScript Handbook           technical-paper
```

The legacy PDF locators are preserved as artifact locators. The publication Record and the PDF artifact remain distinct identities under R0.5/R0.4.

## 8. Evidence reconciliation

R0.0 froze two overlapping evidence catalogs. R0.8 first unions them by exact locator so one locator receives one migration treatment.

Existence-oriented material can be planned directly under R0.4, for example:

```text
public source URL       -> source / source-existence
public PDF              -> document / document-existence
public deployment URL   -> deployment / deployment-existence
```

Three locators cannot be promoted to occurrence Evidence from the freeze alone:

```text
https://vira.snelabs.space/ready
https://vira.snelabs.space/public/playback
https://www.youtube.com/watch?v=LnOd2kWTiGA
```

They are marked `recapture-required` because R0.4 occurrence facets require an immutable digest and `observedAt`. The old locator remains preserved, but R0.8 refuses to manufacture historical runtime proof that R0.0 never captured.

No `evidence.binding` is created in R0.8 because a Binding requires exact pinned Evidence and Claim/Experiment revisions. Those revisions do not exist until Birth.

## 9. Legacy route compatibility

All eight frozen R0.0 routes remain covered.

The root and architecture paths are service/collection identities:

```text
/              home service route
/architecture  architecture-index service route
```

They are not forced into a single Record identity.

The six legacy `/work/:projectId` routes are also not represented as R0.7 aliases. They previously served both EN and PT through client state, while a R0.7 route binding has one explicit language identity.

They therefore become planned **language-negotiating compatibility entry points**:

```text
/work/vira
    -> /en/systems/vira
    -> /pt-br/systems/vira
```

and similarly for the remaining five legacy work routes. The default compatibility language remains EN because the frozen application defaulted to EN; existing language preference may be used by the future compatibility layer.

The old path remains reachable, but it never becomes ambiguously bound to two R0.7 languages.

## 10. Target canonical routes

New Record locators follow the frozen R0.7 grammar.

Examples:

```text
/en/systems/vira
/pt-br/systems/vira

/en/research/verify-systems
/pt-br/research/verify-systems

/en/architecture/realtime
/pt-br/architecture/realtime
```

The migration manifest plans canonical routes but does not enact them during R0.

## 11. Language migration

The frozen project and architecture sources contain explicit EN/PT representations and the legacy application defaulted to EN.

For those migrated entities R0.8 plans:

```text
canonical language  en
translation         pt-BR
```

Production Systems Handbook and TypeScript Handbook are not forced to become bilingual merely because the old interface surrounding their links was localized. Their migration plan initially exposes only the canonical EN realization until an actual translation is admitted.

Language bindings themselves cannot be minted until exact born revisions and realization digests exist.

## 12. Known runtime mismatches remain explicit

R0.8 records three target corrections for R1 rather than pretending R0 changed runtime behavior:

All are R1 work.

## 13. No semantic-loss claim

`semanticLossCount=0` does not mean every old string becomes a dedicated Record.

It means every R0.0 frozen semantic unit receives an explicit preservation treatment:

```text
Project identity          mapped
Project guarantee         mapped
Architecture view         mapped
Architecture guarantee    preserved as representation text
Evidence locator          artifact plan or recapture-required
Publication               mapped
Public route              compatibility plan
Visibility                decomposed
Known runtime drift       explicit deferred correction
```

Nothing is silently dropped, and no weak legacy fact is silently promoted into a stronger epistemic fact.

## 15. Normative migration laws

The machine-readable contract freezes RMA-01 through RMA-20.

The central boundary is:

```text
migration completeness
    != implementation completeness
```

R0.8 proves that the old semantic world fits the new constitutional model. R1 materializes and renders that world.
