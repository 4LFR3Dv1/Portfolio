# R2.1 — Astro Shell Materialization & Editorial Renderer

Status: **MATERIALIZED / AWAITING TERMINAL CI WITNESS**

Baseline: `main@b2fad19a962c7cee304d165d7bbeead5118fd27e`

R2.1 is the first cut that physically produces the new editorial HTML. It does so without changing the deployed React/Vite runtime.

## 1. Physical build graph

The publication shell is isolated under `editorial-shell/`:

```text
editorial-shell
├── package.json
├── package-lock.json
├── astro.config.mjs
├── scripts/
└── src/
```

The accepted package graph is:

```text
Node >= 22.12
Astro 7.2.9
Vite 8.2.2
```

The root application remains on its historical Vite build. `vercel.json` is unchanged.

## 2. Privileged reconstruction is not renderer authority

The initial physical prototype proved Astro could render the accepted state, but it also exposed a boundary problem: letting an Astro module reconstruct the Record Registry and Governance directly would make the renderer itself an institutional reader.

R2.1 therefore splits the physical build into two processes:

```text
canonical R1 manifests
        ↓
privileged prebuild materializer
src/editorial/renderer-input.ts
        ↓
bounded AcceptedRendererInput
        ↓
generated build-only JSON
        ↓
Astro renderer
        ↓
HTML
```

The generated renderer input contains only:

```text
accepted distributed pages
public Editorial Documents
Core Surface DTOs
Publication Shell Plan
accepted completion identifiers
Distribution digest
```

It contains no omitted document decisions, no disclosure rationale, no Evidence corpus and no private semantic source.

`editorial-shell/src/generated/` is ignored by Git. The generated JSON is derived build state, not a new content authority.

## 3. Canonical page generation

Astro `getStaticPaths()` consumes only `AcceptedRendererInput.pages`.

Current physical output target:

```text
12 Core Surface pages
 6 public System document pages
──────────────────────────────
18 canonical static pages
```

The System documents are exactly the EN/PT-BR realizations of:

```text
VIRA
XS Wallet / Domini
SNE-OS
```

Transactional Support Bot and Foundry Pay remain absent because R1 intentionally has no independently admitted sanitized semantic document for them.

## 4. Explicit 404

R2.1 also materializes `404.html` with the target meaning:

```text
unknown path
    → unresolved / 404
```

This output is physical in the Astro build but is not yet active on the production domain.

## 5. What R2.1 deliberately does not render

R2.3 remains responsible for the four preserved historical representations:

```text
/architecture
/work/agentic-systems
/work/transactional-support-bot
/work/verify-systems
```

R2.4 remains responsible for compatibility redirects.

R2.2 remains responsible for physically emitting sitemap, RSS and search artifacts.

Therefore R2.1 does not manufacture placeholder content merely to fill those future cuts.

## 6. Renderer shape

The first shell uses a restrained reading-oriented editorial layout while retaining precise System identity facts where useful.

The shell is presentation only. It may format an admitted System document, but it cannot mint a Record, change disclosure, infer a translation, choose a different head or derive a sanitized public narrative from private source.

React islands remain allowed by the R2.0 boundary but none are required by this cut.

## 7. Physical CI commissioning

A dedicated `Editorial Shell Build` workflow performs:

```text
npm ci
    ↓
materialize bounded renderer input
    ↓
astro build
    ↓
verify physical static output
    ↓
preserve dist + lock witness
```

The physical output verifier requires exactly 18 canonical `index.html` pages plus `404.html`, verifies representative System identities and fails if any R2.3 legacy-preserved page leaks into this cut.

## 8. Deployment boundary

R2.1 does not change:

```text
root package.json build = vite build
vercel.json
public/sitemap.xml
legacy React routing
legacy production UI
production domain runtime
```

So:

```text
ASTRO HTML EXISTS IN CI
        !=
ASTRO HTML IS DEPLOYED
```
