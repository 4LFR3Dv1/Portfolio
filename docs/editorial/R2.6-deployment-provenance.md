# R2.6 — Deployment Provenance Gate

Status: **REQUIRED**

R2.6 cannot admit a public preview merely because a hosting service is configured to follow `r2/shadow-preview-deployment`.

The physically deployed snapshot itself must prove exact provenance.

## Acceptance law

```text
configured source branch
        !=
deployed snapshot provenance
```

A preview deployment is admissible only when provider deployment metadata binds all of:

```text
repository = 4LFR3Dv1/Portfolio
branch     = r2/shadow-preview-deployment
commit     = exact witnessed R2.6 head
```

If the provider reports `main`, an earlier SHA or any other source snapshot, that deployment is rejected as an R2.6 witness even if the service configuration subsequently points at the correct branch.

## Why this gate exists

During the first isolated Railway materialization, the service source configuration was set to `r2/shadow-preview-deployment`, but the first deployment snapshot reported `branch=main` and commit `089f99298e895f299711449516efa55099f987f0`.

That deployment remained fully isolated from the production site, but it cannot establish R2.6 environmental invariance because it did not prove that the R2.6 specimen itself crossed the hosting boundary.

R2.6 therefore distinguishes:

```text
preview infrastructure exists
        !=
correct specimen deployed
        !=
correct specimen publicly reachable
        !=
correct specimen semantically invariant
```

Only the last state can close the cut.
