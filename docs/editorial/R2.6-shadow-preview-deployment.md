Status: **COMPLETE / PUBLIC INTERNET WITNESSED**

Baseline: `main@089f99298e895f299711449516efa55099f987f0`

R2.6 crosses the local commissioning boundary and proves that an external hosting environment preserves the already-accepted R2.5 runtime without changing `renan.snelabs.space`.


## 4. Deployment provenance discovery

The first provider materialization exposed a real environmental issue: service configuration and deployed snapshot provenance are distinct facts.

Two snapshots were rejected:

```text
4579a74f-a000-4a82-8b8c-ff0519854b89
branch=main
commit=089f99298e895f299711449516efa55099f987f0

 d3a0869e-8998-4608-8aa7-037f6bf5e8b7
branch=main
commit=089f99298e895f299711449516efa55099f987f0
```

Neither could witness R2.6 even though the isolated service was subsequently configured for the correct branch.

The accepted snapshot is the first deployment whose provider metadata physically binds the R2.6 branch and exact specimen commit. This rule is frozen separately in `R2.6-deployment-provenance.md`.

## 5. Environmental invariance campaign

The GitHub `Editorial Shell Build` runner started a fresh local R2.5 commissioned runtime and compared it over real HTTPS with the isolated Railway origin.

The campaign covered:

Transport-level differences such as provider request IDs, `Server`, `Date`, HTTP transport and content encoding are observable but not semantic authority.

The following remained invariant after transport normalization:

- decoded response bodies;
- HTTP status codes;
- canonical `Link` state and values;
- `Content-Language`;

- redirect `Location`;
- MIME/content types;
- every locally required cache directive;
- `X-Content-Type-Options: nosniff`.
