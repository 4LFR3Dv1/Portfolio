# R2.6 — Shadow / Preview Deployment

Status: **MATERIALIZED / AWAITING PUBLIC WITNESS**

Baseline: `main@089f99298e895f299711449516efa55099f987f0`

R2.6 is the first cut that crosses the local commissioning boundary and asks whether an external hosting environment preserves the already-accepted R2.5 runtime.

It does not authorize cutover and it does not modify `renan.snelabs.space`.

## 1. Regime change

R2.5 established one physically commissioned local HTTP runtime. R2.6 does not reinterpret or rebuild that semantic boundary.

```text
R2.5 commissioned runtime
        ↓
R2.6 deployment binding only
        ↓
isolated public HTTPS preview
        ↓
DNS / Internet / TLS / proxy / CDN / hosting
        ↓
external observation
        ↓
normalized comparison with local R2.5 observation
```

The acceptance question is:

```text
same commissioned specimen
        +
new transport environment
        ↓
same observable semantics?
```

## 2. Source specimen

The semantic runtime remains:

```text
editorial-shell/runtime/commissioned-runtime.mjs
```

R2.6 adds `editorial-shell/runtime/preview-runtime.mjs`, whose only deployment responsibility is to instantiate `createCommissionedRuntime()` and bind it to:

```text
0.0.0.0:$PORT
```

The R2.5 server implementation is not edited by the preview adapter.

## 3. Isolated deployment artifact

`editorial-shell/preview.Dockerfile` packages the repository, installs the locked editorial-shell dependency graph, builds the exact Astro static output and starts the R2.6 preview entrypoint.

The deployment artifact is intentionally independent from the root production deployment contract.

```text
root package build       vite build        unchanged
root vercel.json         unchanged
production React SPA     authoritative
production DNS           unchanged
production origin        untouched
preview origin           provider-managed / isolated
```

No production hostname is required for R2.6. A provider-generated HTTPS origin is preferred because it makes the hosting boundary directly observable without DNS cutover effects.

## 4. Environmental invariance contract

The frozen contract is:

```text
docs/editorial/preview-environmental-invariance.v0.json
```

Transport-level differences are observable but not automatically semantic failures:

- HTTP/1.1 versus HTTP/2 or HTTP/3;
- gzip / brotli / identity encoding;
- provider `Server`, `Via`, request-id, `Date`, `Age` or equivalent headers;
- TLS termination outside the Node process.

Semantic properties must remain invariant after transport normalization:

- decoded response body;
- HTTP status;
- canonical `Link` presence/value;
- `Content-Language` presence/value;
- `X-Robots-Tag` presence/value;
- redirect `Location` presence/value;
- content type;
- required cache directives;
- `X-Content-Type-Options: nosniff`.

A provider may add stricter compatible cache directives, but it may not remove any directive required by the R2.5 response.

## 5. Public witness campaign

`editorial-shell/scripts/verify-preview-invariance.mjs` starts the R2.5 commissioned runtime locally and compares it physically with `PREVIEW_ORIGIN` over real HTTPS.

The campaign covers:

```text
18 canonical pages
4 historical pages
4 compatibility handshake pages
8 language-specific redirects
explicit-language-required failure path
physical 404
authoritative sitemap
two RSS feeds
search index
complete remaining static asset graph
warm repeated request
TLS certificate validation
```

`fetch()` transparently decodes transport compression before body hashing. Therefore body equality is measured after transport encoding has been removed.

The witness also records provider-specific transport headers without making them semantic authority.

## 6. TLS witness

The verifier performs a separate TLS connection using Node's default trusted CA validation with `rejectUnauthorized=true` and records:

- authorization state;
- negotiated TLS protocol;
- certificate subject CN;
- issuer CN;
- validity interval;
- SHA-256 certificate fingerprint.

An invalid public TLS chain is an R2.6 failure even if HTTP content would otherwise match.

## 7. Production exclusion

The witness rejects these origins explicitly:

```text
https://renan.snelabs.space
https://www.renan.snelabs.space
```

The R2.6 workflow contacts only the supplied preview origin. Production remains outside the campaign.

The existing root Vercel SPA rewrite remains unchanged and is not reused as the preview transport because it would reinterpret unknown extensionless routes as `/index.html`, conflicting with the commissioned physical 404.

## 8. CI and witness workflow

The ordinary Editorial Shell Build now additionally proves that the same commissioned runtime can bind through the R2.6 preview adapter without changing canonical, redirect or 404 behavior.

The separate `Editorial Preview Witness` workflow is manual and requires an explicit HTTPS `preview_origin`.

It performs:

```text
locked install
→ Astro build
→ R2.5 commissioning campaign
→ R2.6 preview binding campaign
→ real HTTPS environmental comparison
→ JSON witness artifact
```

The workflow always attempts to preserve `r2-6-preview-witness.json`, including on semantic comparison failure.

## 9. Acceptance boundary

Materialization alone cannot close R2.6.

The following must be physically true on an isolated public origin:

```text
PUBLIC_PREVIEW_DEPLOYED=true
PUBLIC_TLS_WITNESSED=true
INTERNET_COMPARISON_WITNESSED=true
SEMANTIC_DIFFERENCE_COUNT=0
PRODUCTION_MUTATION_COUNT=0
```

Until that public witness exists:

```text
R2_6_COMPLETE=false
CUTOVER_READY=false
CUTOVER_AUTHORIZED=false
```

After a successful public witness, R2.6 can be terminally sealed and only then may R2.7 evaluate cutover readiness.
