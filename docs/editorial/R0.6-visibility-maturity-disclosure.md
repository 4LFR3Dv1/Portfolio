# R0.6 — Visibility / Maturity / Disclosure

Status: **FROZEN**

Portfolio baseline: `main@ad8ccec1ddf6796de7312172e6b356c6705da516`

Precondition: `R0_5_COMPLETE=true`.

R0.6 freezes the policy layer that decides how already-defined Records may be exposed and how System maturity may be classified without mutating knowledge, evidence or representation payloads.

It adds exactly two RecordKinds:

```text
governance.disclosure
governance.maturity
```

The governing separation is:

```text
what a Record is               R0.2 / R0.3
what supports it               R0.4
how it is represented          R0.5
how it may be exposed          R0.6 disclosure
how mature a System is         R0.6 maturity
```

No earlier frozen payload gains `visibility`, `maturity` or disclosure fields.

## 1. Disclosure is an external policy Record

A `governance.disclosure` Record governs one durable target identity while binding every policy revision to one exact target revision.

```ts
{
  schemaVersion: 'governance.disclosure/v0'
  targetRef: RecordRef
  basisRef: PinnedRecordRef
  visibility: {
    record: 'public' | 'private'
    source: 'public' | 'partial' | 'private' | 'not-applicable' | 'unknown'
    evidence: 'public' | 'partial' | 'private' | 'none' | 'unknown'
  }
  disclosure: 'full' | 'sanitized' | 'metadata-only' | 'withheld'
  rationale: string
}
```

`targetRef` answers which logical Record is governed. `basisRef` answers which exact revision was classified. They MUST identify the same `RecordId`.

## 2. Visibility is multidimensional

R0.6 explicitly rejects the old one-dimensional idea that one label such as `public`, `private` or `case-study` can describe every exposure property.

The three frozen visibility axes are independent:

```text
record visibility
  can this Record revision participate in a public projection?

source availability
  is implementation/source material publicly available?

evidence availability
  is evidential material publicly available?
```

Therefore:

```text
public Record != public source
public Record != public Evidence
private source != private Record
no public Evidence != false Claim
```

`unknown` is preserved as an explicit state for source and Evidence availability. Absence of information MUST NOT be converted into `private`, `none` or `public`.

## 3. Disclosure form is separate from visibility

Record visibility answers whether the Record may be projected publicly. Disclosure mode answers which form may be exposed:

```text
full
sanitized
metadata-only
withheld
```

Compatibility is frozen:

```text
record = public  -> full | sanitized | metadata-only
record = private -> withheld
```

This prevents a private classification from being paired with a public body and prevents `public + withheld` from becoming an ambiguous state.

## 4. Sanitized means admitted public-safe representation

`sanitized` does not authorize the runtime to read private material and redact it automatically.

It means the governed target revision is already the bounded public-safe form that may be projected.

The disclosure Record contains no private source locator, private Evidence locator, secret material or hidden original payload. Private knowledge MUST NOT enter the public repository merely because a governance label says `sanitized`.

Sanitization is therefore an admission boundary, not a transformation engine.

## 5. Disclosure is revision-bound and does not silently inherit

A disclosure policy applies only when:

```text
targetRef.recordId == current target RecordId
basisRef == exact current target head revision
```

If the target Record advances to a new revision and no disclosure revision binds that new head, current disclosure state becomes `unclassified`.

The old decision remains historically reconstructable but does not silently authorize new content. This is deliberate fail-closed behavior.

## 6. One current disclosure authority

For one exact target head, current governance may resolve to:

```text
unclassified
classified
conflict
```

Current projection counts only `active` and `archived` governance Records.

If two distinct current `governance.disclosure` Records classify the same exact target head, the state is `conflict`.

R0.6 forbids `latest governance record wins`, `first file wins`, route precedence and permissiveness as conflict resolution rules. Conflict blocks public eligibility until explicitly reconciled.

## 7. Public projection eligibility

A target may be projected publicly only when:

```text
target lifecycle = active | archived
AND current disclosure state = classified
AND visibility.record = public
AND disclosure != withheld
```

A target whose current lifecycle is `withdrawn` or `tombstoned` is not currently public-projectable even if an older disclosure Record remains historically available.

This rule does not modify the legacy Portfolio UI during R0.

## 8. Disclosure revisions preserve target identity

For one logical `governance.disclosure` lineage, `targetRef.recordId` is constitutive.

The following may change through normal R0.2 successor revisions:

```text
basisRef
visibility axes
disclosure mode
rationale
```

Changing the governed logical target creates another governance Record.

## 9. Maturity is a separate governance Record

A `governance.maturity` Record classifies development maturity without modifying the System payload.

```ts
{
  schemaVersion: 'governance.maturity/v0'
  targetRef: RecordRef
  basisRef: PinnedRecordRef
  stage:
    | 'concept'
    | 'research'
    | 'prototype'
    | 'pre-beta'
    | 'beta'
    | 'production'
    | 'completed'
  rationale: string
}
```

Maturity applies only to `knowledge.system`.

Questions, Investigations and Experiments already have their own domain states. Publications and Architecture are representations. Evidence has evidential lifecycle. R0.6 does not impose System maturity on those kinds.

## 10. Maturity is not visibility

These are valid combinations:

```text
production + private
research + public
prototype + sanitized
completed + metadata-only
```

No maturity stage implies public exposure. No disclosure mode implies maturity. No source availability implies maturity.

## 11. Maturity is not Evidence

The stage `production` does not establish deployment existence, runtime health, test success, security or correctness. Those statements require appropriate R0.4 Evidence and explicit bindings.

Maturity is an admitted classification, not an evidential verdict.

## 12. Maturity is not monotonic

R0.6 freezes no ordering authority such as `production > beta > prototype` for truth, quality or permanence.

A later classification may move in any direction through a new governance revision because systems can be downgraded, re-scoped or reconstructed. Generation order remains R0.2 lineage order only.

## 13. Maturity is revision-bound

Like disclosure, current maturity is valid only when its `basisRef` matches the exact current System head.

A new System revision without a matching maturity revision yields `unclassified` rather than silently inheriting a possibly stale maturity claim.

## 14. Governance Records are control-plane Records

R0.6 governance Records may target only kinds frozen before R0.6:

```text
knowledge.*
evidence.*
representation.*
```

They do not target other governance Records in this cut. This avoids recursive exposure policy and keeps R0.6 as a bounded control plane above the existing semantic graph.

## 15. Canonical payload profile

Both governance kinds use the canonical editorial JSON profile:

- UTF-8;
- lexicographically sorted object keys;
- no insignificant whitespace;
- terminal LF;
- exact field sets;
- SHA-256 `PayloadDigest`;
- no implicit values.

R0.6 includes independent canonical payload vectors for both governance kinds.

## 16. Legacy mapping intent

R0.6 is designed to replace the current overloaded legacy visibility field during R0.8 migration.

Examples of intended decomposition:

```text
legacy public system
  record visibility   public
  disclosure          full
  source              public | private | unknown
  evidence            public | partial | private | none | unknown

legacy case-study / sanitized case
  record visibility   public
  disclosure          sanitized
  source              private
  evidence            private | partial

non-public system
  record visibility   private
  disclosure          withheld
```

This section is migration intent only. R0.6 does not migrate legacy `Project` objects.

## 17. Explicitly deferred

R0.6 does not define slug grammar, route identity, canonical URL, redirects, language identity, translation identity, locale routing, legacy Project migration, legacy EvidenceRoom migration or final public UI.

Those remain R0.7 and R0.8.
