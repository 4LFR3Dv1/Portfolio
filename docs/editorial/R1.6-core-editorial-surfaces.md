# R1.6 — Core Editorial Surfaces

Status: **MATERIALIZED / AWAITING CI WITNESS**

Baseline: `main@89d279400a497b794310543a074462ef10b9d65b`

Preconditions:

```text
R0_EFFECTIVE_COMPLETE=true
R1_1_COMPLETE=true
R1_2_COMPLETE=true
R1_3_COMPLETE=true
R1_4_COMPLETE=true
R1_5_COMPLETE=true
```

R1.6 materializes the first renderer-neutral editorial surface models without replacing the deployed React/Vite application.

The cut has two responsibilities that must remain separate:

```text
explicit governance admission
        ↓
public projections / documents
        ↓
core surface queries
```

and never:

```text
surface component → invent disclosure
surface component → infer ranking
surface component → infer translation
surface component → become Record authority
```

## 1. First enacted governance is explicit, not inferred

R1.2 could evaluate disclosure, but the new substrate intentionally had no admitted governance Records through R1.5.

R1.6 admits only six generation-zero governance Records whose semantics were already frozen by R0.8 and whose System targets were actually Born in R1.1:

```text
5 × governance.disclosure
1 × governance.maturity
```

The five disclosure targets are exactly the five Systems with valid R1.3 canonical routes:

```text
VIRA
XS Wallet / Domini
Transactional Support Bot
SNE-OS
Foundry Pay
```

No policy is inferred for the other twenty-three Born Systems.

Every governance assignment binds an exact R1.1 System revision through `basisRevisionId`. A later System head does not silently inherit the R1.6 decision.

The governance RecordId is distinct from the target System RecordId and is itself born under R0.2 generation-zero identity rules.

## 2. Effective disclosure outcomes

The frozen R0.8 plans enact:

```text
VIRA                         public / full
XS Wallet / Domini           public / full
Transactional Support Bot    public / sanitized
SNE-OS                       public / full
Foundry Pay                   public / sanitized
```

XS Wallet additionally receives the explicitly frozen:

```text
maturity = pre-beta
```

This maturity remains a declared classification. It is not Evidence of runtime operation, deployment, correctness or security.

## 3. Sanitized still does not mean runtime redaction

R1.5 established that a sanitized disclosure decision does not authorize the renderer to load canonical content and redact it dynamically.

Therefore the two sanitized Systems produce valid public projections but no semantic Editorial Document until a separate disclosure-safe content authority exists.

Current effective result:

```text
10 routed language pairs
        ↓
10 public projections
        ↓
6 full Editorial Documents
4 sanitized-content-authority-unavailable
```

The four omissions are EN + PT-BR for:

```text
Transactional Support Bot
Foundry Pay
```

No private source or private Evidence content is exposed by omission.

## 4. Core surfaces are deterministic queries over Documents

R1.6 materializes six surface families for each admitted language:

```text
Home
Systems
Archive
Research
Essays
Notes
```

with explicit service paths:

```text
/en
/en/systems
/en/archive
/en/research
/en/essays
/en/notes

/pt-br
/pt-br/systems
/pt-br/archive
/pt-br/research
/pt-br/essays
/pt-br/notes
```

These are surface/service identities, not Record locators and not R0.7 Record RouteBindings.

R1.6 does not synthesize a Record route from a surface path and does not assign a RecordId to a collection merely because a collection is renderable.

## 5. No featured/ranking inference

The substrate currently has no admitted editorial ranking, publication timestamp ordering or featured-content authority.

Therefore R1.6 freezes:

```text
rankingInferenceAllowed=false
chronologyInferenceAllowed=false
```

Items are sorted only by canonical path to make builds deterministic. This ordering is implementation determinism, not editorial importance.

Home composes the already-defined Systems, Research, Essays, Notes and Archive sections. It does not invent a featured hierarchy.

Because the only Born semantic content adapter in R1.5 is `knowledge.system`, and because only three routed Systems currently have full disclosure-safe content, each language has:

```text
Systems     3

Research    0
Essays      0
Notes       0
```

The three current System documents are:

```text
SNE-OS
VIRA
XS Wallet / Domini
```

Research, Essays and Notes remain empty rather than borrowing PDFs, README prose or legacy JSX before their representation Records are explicitly Born.

## 7. Language separation remains exact

EN surfaces consume only EN Editorial Documents.
PT-BR surfaces consume only PT-BR Editorial Documents.

A document does not cross language surfaces because another locale is empty or because the canonical Record language exists.

There is no fallback at the surface layer.

## 8. Surface DTOs are not semantic authority

A surface item may carry public document fields such as:

```text
targetRef
kind
canonicalPath
canonicalUrl
title
summary
maturity
```

because these values have already crossed the Projection + Language + Document boundaries.

The surface runtime cannot:

```text
mint Records
change current heads
change disclosure
change maturity
create translations
create Evidence support
reinterpret canonical payload
```

## 9. No Astro cutover yet

R1.6 does not install or activate the Astro publication shell.

It does not enact:

```text
static HTML rendering
framework cutover
Vercel deployment changes
legacy route replacement
RSS
sitemap
search index
```

The current deployed React/Vite site therefore continues unchanged.

The new surfaces exist as deterministic DTOs that the later publication shell can render.
