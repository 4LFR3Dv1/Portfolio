# R0.4 — Evidence Contract

Status: **FROZEN**

Portfolio baseline: `main@dae52fdafc58a39bcef0c7f515284785acc9d497`

Precondition: `R0_3_COMPLETE=true`.

R0.4 defines how evidence can exist, retain provenance and be related to exact knowledge states without allowing an artifact to manufacture its own conclusion. It adds two RecordKinds:

```text
evidence.artifact
evidence.binding
```

The split is constitutional: **an artifact is not a claim and a support relation is not the artifact itself**.

## 1. Evidence artifact

`evidence.artifact` represents one durable evidential source or captured occurrence.

```ts
{
  schemaVersion: 'evidence.artifact/v0'
  evidenceClass:
    | 'source'
    | 'commit'
    | 'test'
    | 'deployment'
    | 'endpoint'
    | 'document'
    | 'physical-witness'
    | 'video'
    | 'dataset'
    | 'artifact'
  title: string
  provenance: {
    origin: string
    locator: string | null
    observedAt: string | null
    digest: `sha256_${string}` | null
  }
  facets: EvidenceFacet[]
}
```

Evidence class and provenance describe **what was admitted and where it came from**. They do not encode the conclusion drawn from it.

## 2. Immutable evidential core

Across revisions of the same `evidence.artifact`, these fields are constitutive evidential core and MUST remain unchanged:

```text
evidenceClass
provenance.origin
provenance.locator
provenance.observedAt
provenance.digest
```

`title` and `facets` may be revised through normal R0.2 lineage. A material change to the captured source or occurrence creates a new Evidence Record rather than rewriting the old one.

This preserves the N1-style boundary already reflected in the Editorial Constitution: later interpretation cannot rewrite source evidence.

## 3. Evidence facets

A facet states the domain in which an artifact is admissible for a later binding. It is not a conclusion.

```text
source-existence
source-state
test-result
deployment-existence
runtime-observation
endpoint-observation
document-existence
physical-observation
visual-observation
dataset-observation
artifact-integrity
```

Evidence class constrains which facets may be admitted. For example, source code can establish source existence/state but does not become runtime evidence merely because it is public.

## 4. Provenance strength rules

An Evidence Artifact MUST contain at least a locator or a digest.

Existence-oriented facets may be locator-bound:

```text
source-existence
deployment-existence
document-existence
```

Content/state facets require an immutable digest:

```text
source-state
test-result
runtime-observation
endpoint-observation
physical-observation
visual-observation
dataset-observation
artifact-integrity
```

Occurrence-oriented facets also require `observedAt`:

```text
test-result
runtime-observation
endpoint-observation
physical-observation
visual-observation
dataset-observation
```

Therefore a live URL alone is not runtime proof. It is at most a locator until a bounded observation is captured and bound.

## 5. Evidence binding

`evidence.binding` is the explicit epistemic assertion relating one exact Evidence revision to one exact Claim or Experiment revision.

```ts
{
  schemaVersion: 'evidence.binding/v0'
  relation: 'supports' | 'contradicts' | 'qualifies'
  facet: EvidenceFacet
  evidenceRef: PinnedRecordRef
  targetRef: PinnedRecordRef
  scope: string
  rationale: string
}
```

Both ends are pinned. A later revision of the Evidence, Claim or Experiment does not retroactively change what the binding meant.

## 6. Binding target boundary

R0.4 permits bindings only to exact revisions of:

```text
knowledge.claim
knowledge.experiment
```

For an Experiment, the binding concerns the `declaredOutcome` present in that exact revision. For a Claim, it concerns the exact statement/scope revision.

Publication and Architecture citation semantics remain deferred to R0.5.

## 7. Facet compatibility

A binding is admissible only when:

```text
binding.facet ∈ evidenceArtifactRevision.facets
```

This blocks a `source-existence` artifact from being reused as `runtime-observation` without a separate evidential admission that satisfies the stronger provenance rules.

## 8. Binding core continuity

For one logical `evidence.binding`, these fields are constitutive and remain unchanged across revisions:

```text
relation
evidenceRef
targetRef
facet
```

`scope` and `rationale` may be revised while R0.2 preserves their history. Rebinding to different evidence, a different target revision, another facet or the opposite relation creates a new Binding Record.

## 9. Withdrawal and current evaluation

Historical bindings remain reconstructable. Current evidential projections, however, count only bindings whose logical Binding Record and logical Evidence Artifact Record are currently `active` or `archived`.

A current head that is `withdrawn` or `tombstoned` removes that Evidence or Binding from the current disposition without rewriting historical pinned relations.

## 10. Evidential disposition

R0.4 defines a mechanical projection over currently admissible bindings for one pinned target:

```text
unassessed
support-present
contradiction-present
mixed
qualification-only
```

This projection is deliberately weaker than truth ranking.

```text
support-present       != established
contradiction-present != refuted
mixed                  != false
unassessed             != unsupported-by-reality
```

R0.4 does not create automatic `established` or `refuted` states.

## 11. Evidence does not self-authorize claims

An artifact may exist without any Binding.

A Claim may exist without any Evidence Binding.

A Binding records an explicit interpretation between them. This preserves:

```text
Evidence != Claim
Claim != Evidence
Artifact != Binding
Binding != Truth
```

## 12. Canonical payloads

Both R0.4 kinds use the canonical JSON profile established for editorial semantic payloads:

- UTF-8;
- object keys lexicographically sorted;
- no insignificant whitespace;
- terminal LF;
- exact field sets;
- no implicit values;
- SHA-256 `PayloadDigest`.

R0.4 includes independent test vectors for both payload kinds.

## 13. Explicitly deferred

R0.4 does not define:

```text
Publication citation UI
Architecture evidence projection
public/private/partial evidence visibility
maturity
route grammar
language identity
legacy EvidenceRoom migration
automatic truth ranking
```

Visibility of evidence belongs to R0.6; legacy reconciliation belongs to R0.8.
