R1.7 materializes distribution as a deterministic consumer of the already-authorized R1.6 surface and document state.

It does not create a second page registry.

The direction of authority is:

```text
admitted Records + governance
        ↓
Projection Engine
        ↓
Language Runtime
        ↓
Editorial Documents
        ↓
Core Editorial Surfaces
        ↓
Distribution Foundation
```

and never:

```text
sitemap → decide what is public
search index → discover hidden Records
RSS → manufacture chronology
metadata → become canonical identity
hreflang → imply a translation exists
```

## 1. One authorized page set

The R1.7 page set is derived from only two already-authorized inputs:

```text
R1.6 Core Surface DTOs
+
R1.5 semantic Editorial Documents that actually reached R1.6
```

No array of Record routes, legacy projects or GitHub repositories is copied into the distribution layer.

The current derived set is:

```text
12 core service surfaces
 6 semantic public documents
────────────────────────────
18 indexable pages
```

The six document pages are the EN/PT-BR realizations of:

```text
SNE-OS
VIRA
XS Wallet / Domini
```

Transactional Support Bot and Foundry Pay are absent because their public disclosure is `sanitized` but no independently admitted disclosure-safe semantic document exists.

Unrouted or ungoverned born Systems are also absent.

## 2. Canonical metadata is derived, not authoritative

Every distributed page receives a renderer-neutral metadata entry containing:

```text
canonicalPath
canonicalUrl
language
title
description
robots
hreflang alternates
```

For Record-backed pages, title and description come only from the already-authorized Editorial Document.

For service surfaces, localized labels and descriptions are presentation metadata for the surface identity. They do not create Records or Claims.

Canonical metadata does not mint URL identity. Record canonical URLs continue to come from R0.7/R1.3 route authority.

## 3. Hreflang means equivalent public realization exists

R1.7 groups localized equivalents only when both pages are present in the authorized distribution set.

Current clusters:

```text
6 surface families
3 System revision identities
────────────────────────────
9 hreflang clusters
18 language links
```

There is no inferred `x-default` and no cross-language fallback.

A missing translation produces no hreflang link.

## 4. Sitemap follows the same page set

The future editorial sitemap is derived from the exact same eighteen pages used by canonical metadata.

R1.7 does not infer:

```text
lastmod
priority
changefreq
```

because no corresponding authority exists yet.

The existing deployed `public/sitemap.xml` is not replaced by this cut. Legacy distribution remains active until the later compatibility/cutover boundary.

## 5. RSS exists without inventing chronology

R1.7 materializes two feed envelopes:

```text
/en/rss.xml
/pt-br/rss.xml
```

but both currently contain zero items.

This is intentional. No `representation.publication` Editorial Documents with explicit distribution chronology have been Born and rendered yet, and R1.7 refuses to treat System identity order, Git history, route order or file timestamps as publication chronology.

Therefore:

```text
RSS foundation exists
RSS item count = 0
```

until later admitted publication state supplies the missing authority.

## 6. Search indexes only semantic public documents

The search index contains only documents that have crossed the full public chain and contain semantic document content.

Current state:

```text
6 search entries
3 EN
3 PT-BR
```

Service surfaces are not copied into the semantic search corpus.
Sanitized omissions are not indexed.
Unprojected Records are not indexed.
Private source or Evidence material is not inspected by search construction.

## 7. Structured distribution bundle

Metadata, hreflang, sitemap, RSS and search are assembled into one deterministic structured bundle:

```text
editorial-distribution-bundle/v0
```

The canonical JSON serialization of this bundle receives a SHA-256 digest.

The digest is stable under input array reordering because page and cluster ordering is normalized by canonical path and identity key.

The bundle is a build artifact, not Record authority.

## 8. XML serializers are renderer-neutral build primitives

R1.7 supplies deterministic serializers for:

```text
sitemap XML
RSS XML
```

They do not write to `public/`, do not change Vercel configuration and do not activate Astro.

A later publication shell may emit these artifacts from the same bundle without maintaining another list of URLs.

## 9. Deployment boundary remains unchanged

R1.7 does not enact:

```text
Astro cutover
static HTML publication
legacy route replacement
legacy sitemap replacement
Vercel configuration changes
public UI changes
```

The currently deployed React/Vite site remains unchanged.
